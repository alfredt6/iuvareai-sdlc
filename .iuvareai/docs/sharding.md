# Small-Batch Work Design

Prefer one independently valuable behavior or document outcome per task. A good
batch:

- can be completed in hours to a few days;
- has one concise outcome and testable acceptance;
- names exact output files without pretending discovery is impossible;
- can expand scope explicitly when evidence requires it;
- is independently reviewable and revertible;
- avoids unrelated cleanup;
- uses a contract only when it actually touches that contract.

The old five-file heuristic remains a smell, not a hard gate. Split when review,
verification, rollback, or context quality improves—not merely to satisfy a file
count. Avoid both mega-tasks and administrative sub-test fragments.
